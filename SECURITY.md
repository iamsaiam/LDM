# Reporting a vulnerability

Use [GitHub's private vulnerability reporting](https://github.com/iamsaiam/LDM/security/advisories/new)
when that option is available. If it is unavailable, open an issue asking the
maintainer for a private reporting channel without including exploit details or
sensitive data.

Include the affected commit/version, OS, reproduction steps and impact. Remove
cookies, authorization headers, signed media URLs, local secrets and personal
files from attachments. Reports about an external FFmpeg or libcurl build should
include its version and configuration.

The project is under active development. Check the [verification record](docs/VERIFICATION.md)
for tested builds and the [release guide](RELEASE.md) for helper and distribution
requirements. No response-time or support-window commitment is currently defined.
